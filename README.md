# カードジャム v1.7

ブラウザで遊べる1対1のターン制カードゲーム。あなたがプレイヤー1、AIがプレイヤー2を操作します。相手のライフ20を0にすれば勝利です。

## 準備

双方とも8種類のモンスター各2枚、計16枚の同じ構成をシャッフルします。初期手札は3枚で、コスト2以下を最低1枚保証します。先攻はランダムです。

先攻・後攻の差を抑えるため、先攻も最初の手番にドローし、後攻はコストの伸びが1手番早くなります。

## 共通コスト

- 先攻は自分の手番ごとに2→3→4、後攻は3→4まで毎ターン全回復します。
- 未使用分は持ち越しません。召喚、左右移動、前後交代が同じコストを使います。
- 召喚にはカード右上の数値を支払います。別の行動力や召喚回数制限はありません。
- ダメージを受けても、モンスターが破壊されてもコストは増えません。
- 攻撃は無料。コスト0でも行えます。

## 手番と操作

自分の手番開始時に1枚ドローし、共通コストが回復します。双方とも自分の最初の手番は攻撃できません。

### 召喚

手札を選んで、自分の空きマスをクリックします。配置は2×2です。

```
前列左 | 前列右
後列左 | 後列右
```

前列が空いている列では、後列のモンスターが自動で前列に進みます。召喚・破壊・左右移動時に適用します。

### 攻撃

前列モンスターの「攻撃」ボタンを押します。正面の敵前列、いなければ相手プレイヤーに攻撃します。後列の敵を直接攻撃することはできません。ボタンには「本体に3」「ナイト撃破」「2・反撃1」「反撃で倒れる」など、実行前に結果を表示します。

- 1体につき毎ターン1回、コスト消費なし。
- 召喚ターンは敵モンスターにだけ攻撃できます。直接攻撃は次の自分の手番から可能。
- ダメージは攻撃力の数値。敵モンスターが生き残れば、その敵の攻撃力で反撃します。
- 召喚したモンスターは、直後の相手の手番の間「守り-1」となり、受けるダメージが1減ります（攻撃側の数値が1以下なら0）。直接攻撃には影響しません。
- HP0以下で破壊されます。後列が前進した場合、そのモンスター自身に攻撃が残っていれば攻撃できます。

### 左右移動

モンスター下の「右へ・1」「左へ・1」ボタンを押します。同じ段の反対側が空いていれば、共通コスト1で移動します。各モンスター毎ターン1回まで。

### 前後交代

後列モンスターの「前へ交代 · 1」ボタンを押すと、共通コスト1で同じ列の前列と交代します。各列毎ターン1回まで。

左右移動・前後交代をしても攻撃済み、召喚直後の制限は維持します。攻撃後に移動して身を守ることもできますが、追加攻撃はできません。

### 手番終了

「ターン終了」で終了します。コスト0かつ攻撃可能な前列モンスターもいなくなると、短い待機後に自動終了します。コスト0でも攻撃が残っている間は自分の手番が続きます。

## キーボード操作

Tabで手札・空きマス・各ボタンへ移動し、Enter/Spaceで実行します。Escでカードの選択を解除します。

## 画面の表示

ライフ、コスト、山札残数、手札枚数を常時表示します。山札が0枚になると、次のドローで受ける疲労ダメージを表示します。ログは「あなた」「AI」で表記します。対戦途中の「新しい対戦」は、2回押したときだけ始めます。

## 手札上限と山札切れ

手札は4枚まで。満杯なら手札・山札を保持してドローを見送ります。山札が0枚のときに引こうとすると、手札の枚数にかかわらず、累積疲労ダメージ（1、2、3…）を受けます。

## AI

毎行動の前に、攻撃・前後交代・左右移動を組み合わせてその手番で勝てる手順を探し、あれば実行します。なければ左右移動、攻撃、前後交代、召喚の順に判断します。守りでダメージ0になる攻撃はしません。前後交代は、交代したモンスターがその手番に攻撃できる場合だけ行います。共通コストを使い切っても、可能な攻撃を続けます。

## 起動と検証

`python3 -m http.server 8000 --bind 127.0.0.1` で起動し、[localhost:8000](http://localhost:8000) を開きます。

- `node --test tests/rules.test.cjs`：ルールの回帰テストとAI同士100対戦。
- `node playtests/current-game.cjs`：現在のルールと実際のAIで200対戦を集計。
- `node playtests/ai-compare.cjs [対戦数]`：v1.5方針のAIとの勝率、AI同士の先攻勝率。
- `node playtests/fun-experiments.cjs [対戦数] [案...]`：接戦率・大差率・逆転率などでルール案を比較（`FUN_EXPERIMENTS.md`）。

過去の比較データとレビューは各ファイルに記載したバージョン時点の記録です。現在のルールの数値とは区別してください。
